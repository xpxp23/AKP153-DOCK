# AKP153 控制台

黑爵 AJAZZ AKP153 液晶控制台的**独立驱动 + 配置工具**。不依赖 Bitfocus Companion。

核心交互只有一条：**把文件拖到格子里，按下设备上的键就执行。**

---

## 硬件事实

- **15 个实体键**：6 列 × 3 行里的**列 0–4**（分辨率 96×96）
- **3 块显示屏**：**列 5**，80×80，**按不动**，只能显示
- 物理面板相对图像坐标系旋转 90°，发送前需要旋转（界面上「屏幕方向」可一键切换）
- USB：`VID 0x5548 / PID 0x6674`

## 启动

双击 **`启动 AKP153 控制台.bat`** —— 会直接弹出配置窗口。

> ⚠️ **USB HID 是独占的**：Companion 或原厂驱动不能同时占用这块屏幕。
> 工具内嵌了原厂自启冲突检测与一键禁用，并会自动检测 Companion 并拦下你。

- **手动双击启动** → 运行根目录 `启动 AKP153 控制台.bat` 或便携版 `AKP153 控制台.exe`
- **开机自启**（默认开）→ 写入规范注册表命令，开机静默进托盘，不弹窗口
- 关掉窗口不会退出程序，它仍然在托盘里；**双击托盘图标**重新打开，右键 → 退出

## USB 热插拔自愈

拔掉再插回 USB 会让 HID 句柄失效，而且 Windows 通常会**换一个新的设备路径**——
旧句柄上继续 write 不会报错，只会写进虚空，表现就是"状态显示已连接、但屏幕黑的"。

驱动里有三层保护：

1. **句柄失效立即判定**：设备 `error` 事件一到就把句柄标记为 broken，后续写入直接抛
   `NOT_OPEN`，不再"假装成功"。
2. **后台自愈看门狗**（每 2 秒）：只要没有可用句柄就重新枚举 + 打开 + 强制唤醒，
   成功后通知界面重画。所以**插回去会自动恢复**，不用管。
3. **硬复位**：如果插回后面板通电但不显示，会走一次完整
   `DIS → wake → HAN → sleep → DIS → wake → 亮度` 循环让控制器重新初始化 LCD 流水线。
   界面上的「重连设备」和托盘里的「重连设备（插拔 USB 后用这个）」走的就是这条。

界面状态会显示 `设备已断开 · 自动重连中…`，恢复后自动变回 `已连接 · 推图 N`。

## 排错

- **一闪而过什么都看不到** → 用 `调试模式.bat`
- 任何启动异常都会写进 **`logs/main.log`**，正常启动会有三行：
  `app ready` → `device host ready` → `device opened OK`
- **状态栏显示「设备被 Companion 占用」** → 去 Companion 托盘图标右键 Quit，然后点界面上的「重连设备」
- **Electron 起来就报 `ipcMain is undefined`** → 环境变量里有 `ELECTRON_RUN_AS_NODE=1`，
  它会让 Electron 退化成纯 Node。两个 bat 里都已经 `set ELECTRON_RUN_AS_NODE=` 清掉了。
- **日志全绿、推图不报错，但屏幕是黑的** → 设备处于**休眠**状态。
  Companion 的「自动休眠」会发 `HAN + sleep + LBLIG 0 + LIG 0` 把背光和 LCD 一起断电，
  **Companion 退出后设备仍然保持这个状态**。休眠时推图是写进 LCD RAM 的，屏幕就是不亮。
  本工具在连接时会**强制发一次唤醒序列**（`DIS + wake + 亮度`），托盘菜单和界面上也都有「唤醒」。

## 怎么用

1. 从桌面 / 开始菜单 / 资源管理器里，**直接把东西拖到格子上**：
   - `.exe`、`.lnk` 快捷方式 → 点击启动程序
   - 文件夹 → 点击打开该目录
   - 网址（拖浏览器地址栏的图标，或直接拖文本） → 点击用默认浏览器打开
   - `.ps1` 脚本 → 点击以 PowerShell 运行
   - 任意其它文件 → 用系统默认程序打开
2. 图标和名称会**自动从文件抓取**，不用手填。
3. 点格子可在右侧改：名称、类型、目标、参数、底色、换图标。
4. 格子右上角 `×` 删除。
5. 最右列三块屏：可设为**时钟**或自定义文字。

改完立即生效，不用保存（配置实时写进 `config.json`，也刷新到设备）。

## 为什么驱动跑在独立进程

`device-host.js` 是**纯 Node** 进程，Electron 通过 stdin/stdout 上的 JSON-RPC 跟它说话：

- `node-hid` 直接用官方预编译包，不需要 `electron-rebuild`、不需要装 VS 生成工具
- 驱动崩了不会带崩界面，2 秒后自动重连
- **可以脱离 Electron 单独测试**（`node host/test-draw.js`）

## 休眠方式可切换

不同固件对"关闭背光"的指令顺序要求不一样。顶部「休眠方式」下拉提供 4 种：

| 值 | 序列 | AKP153 实测 |
|---|---|---|
| `zeros-last`（**默认**） | LBLIG 0 → LIG 0 → HAN → sleep | ✅ 彻底黑 |
| `nobright` | HAN → sleep（之后不发亮度指令） | ✅ 彻底黑 |
| `vendor` | HAN → sleep → LBLIG 0 → LIG 0（厂商顺序） | ⚠️ 微亮 |
| `light` | 只降亮度（不执行 HAN/sleep） | ⚠️ 微亮 |

**规律**：只有「以 `HAN + sleep` 结尾」的顺序能彻底断电。
厂商顺序把亮度归零放在最后，那两条 `LBLIG`/`LIG` 写入反而把背光**重新点亮**了一点点——
所以看起来像"变暗"而不是"关屏"。Companion 驱动用的是厂商顺序，因此它有同样的毛病。

换固件/换型号时：跑 `诊断-休眠.bat`，它会依次演 4 种方案，你记住哪种彻底黑屏，在下拉里选它。

每次按键都会记进 `logs/main.log`，格式：

```
key r0c0 -> file E:\...\README.md
  result: ok (launched)
```

`result` 后面的括号说明实际做了什么：`launched` 新启动 / `focused` 唤起已在运行的实例 /
`spawn` 带参数启动。没配按键的格子会记 `NOT CONFIGURED` 并在界面上弹提示。
**排查"按了没反应"先看这个日志。**

## 怎么用（三种方式都能配）

1. **拖**：把文件 / 文件夹 / 快捷方式 / 网址拖进格子
2. **点**：点格子后在右侧「选择程序…」「选择文件夹…」「填网址…」「填命令…」
3. **换**：已配好的格子**互相拖动**即可交换位置

点最右列的显示屏格子，可以设置它显示时钟还是自定义文字。

样式可调：底色、**渐变到**（第二个色 = 上下渐变）、文字色（自动/自定义）、
字号、图标大小、文字位置（顶部/居中/底部）。名称支持回车换行。

### 按下键时会做什么

| 情况 | 行为 |
|---|---|
| 程序没在运行 | 启动它 |
| 程序已在运行（`.exe` / 快捷方式） | 把它的窗口**唤到前台**，不重复启动 |
| 想强制开第二个实例 | 在格子的「参数」里随便填一个字符——有参数时走 spawn，不唤起 |
| 文件夹 / 图片 / 压缩包 / 文档 | 交给系统默认程序打开 |
| 网址 | 默认浏览器打开 |

> 第二行是刻意设计的。绝大多数应用是单实例的，重复启动既不开新窗口也不报错，
> 只会让人以为"按键坏了"——这是最难查的一类假象。

## 界面

```
┌─ 顶栏：设备名 + 状态灯 ──────────── 唤醒/休眠/重连/⚙ ─┐
│                                                        │
│  ┌─ 设备预览（深色外壳，像块硬件）─┐   ┌─ 属性面板 ─┐  │
│  │ AJAZZ AKP-153                  │   │ 动作       │  │
│  │ 15 个可按键 + 右侧 3 块显示屏   │   │ 外观       │  │
│  └────────────────────────────────┘   │ 图标与库   │  │
│                                        └────────────┘  │
├─ 按键库（可折叠抽屉）──────────────────────────────────┤
└────────────────────────────────────────────────────────┘
```

- **窗口默认 1160×800，最小 1000×660，会记住大小和位置**。
  版面最小需要 1000px：设备是固定 6 列，属性面板要保住 344px。
- **设备预览永远完整可见**：格子按 `aspect-ratio` 自适应，从 112px 一直缩到 70px 都不裁切、不滚动。
- **属性面板分三个可折叠小节**（动作 / 外观 / 图标与库），面板内部独立滚动 ——
  否则它自己就有 800px 高，会把底部控件顶出视口。
- **低频设置收进 ⚙ 弹层**（亮度 / 自动休眠 / 休眠方式 / 屏幕方向 / 开机自启 / 全部重画），
  顶栏只留状态和日常动作。
- 空格子只在**悬停或拖拽时**才出现 ＋ 提示（13 个格子都写"拖到这里"太吵）。
- 每个键左下角有**类型徽章**（应用 / 文件夹 / 网址 / 命令 / 脚本），一眼看出这个键是什么。

### 按键库

右下角抽屉（"小态"：随手取一个）+ 「展开」大面板（搜索 + 标签筛选 + 批量操作）。

- **分类用标签，不是文件夹**：一个条目可以同时属于「开发」和「常用」，
  不用为了两处可见而存两份，切分类也不用进进出出。
- 存：在格子上调好 → 点「**存进按键库**」（正筛选着某个标签时会直接带上它）
- **也可以直接把格子拖进库里** —— 拖到抽屉（折叠时拖到「按键库」那一条就行）或
  拖到展开面板上，松手即入库。拖动时标题栏会显示「← 拖到这里存库」。
- **整页快照**：页面栏的「**本页入库**」把这一页的 15 个键 + 3 块屏整体存进库，
  以后可以**建成新页**或**覆盖当前页**回来。库里用 6×3 迷你预览一眼认出来。
- 取：点条目放到当前选中的格子，或**把条目直接拖到格子上**
- 管理（大面板里）：**改名 / 标签 / 用当前格覆盖 / 删除**；
  整页快照是 **建成新页 / 覆盖当前页**
- **导入导出**：`导出全部…`、`只导出当前标签…`、`导入…`（合并，不与已有 id 冲突）
- 存在 `config.json` 的 `library` 数组里，跨页通用
- 单个键用 `spec`，整页快照用 `kind:'page'` + `page:{buttons,strips}` —— 一条数组两种条目

### 机身颜色

顶栏 `⚙` → 「机身颜色」：**白色（默认）** / 深色。
只影响设备外壳和空格子的配色——格子本身的颜色是你自己设的。

### 页面与文件夹

配置是一棵**页面树**：顶层是「页」，页下面可以再挂「子页」＝文件夹。

- **切页键**：任意键都能设成切页动作 —— `下一页 / 上一页 / 跳到指定页 / 返回上级 / 回到主页面`。
  `下一页 / 上一页` **只翻顶层页**，不会钻进子页（子页靠它自己的键进）。
- **子页自带返回键**：进入子页后 **右下角 (r2c4) 自动变成「← 返回」**，退出后你原来放在
  那个角上的按键自动恢复。位置永远一样，闭眼也按得到。界面上标着「自动」，
  而且不能被拖走或覆盖。
- **显示屏可显示页码**：点右列的屏 → 内容选「页码 + 页名」，翻页时自动更新
  （顶层页显示 `第 2/3 页`，子页显示 `子页 · 娱乐`）。
- 编辑器与设备**永远显示同一页**：你在改哪一页，设备上就是哪一页，所见即所得。
- 页面标签栏在顶部，子页会缩进并带 `↳` 前缀。

老配置（扁平的 `buttons` / `strips`）在第一次加载时**自动迁移成第一页**，
按键一个不丢。

### 配置文件热重载

主进程**监听着 `config.json`**：文件被外部改动后约 1 秒内自动重载并重画设备，
**不用重启应用**。

**判定"是不是外部改的"靠比对内容，不靠时间窗。** 这条踩过坑：
早期写成「忽略自己 save 之后 900ms 内的事件」，但那个 4 秒的兜底轮询会在
save 之后 4 秒才看到 mtime 变化，此时早就过了 900ms → **误判成外部修改**。
结果是用户每在界面上动一下，4 秒后必然弹一次「配置已从文件重新导入」，
而每次误报都全屏重画（18 张图推 HID）→ 那几秒按键像失效。

现在：`save()` 记住写出去的原文、`load()` 记住读进来的原文，
`changedOnDisk()` 直接比字符串。自己的写不触发，外部原样重写也不触发。
`npm run test:config` 里有这条的回归用例。

## 八个已知的坑（都已经修好了，记录避免重犯）

**-5. 热重载的守卫不能用"时间窗"猜（见上）**
症状是「运行着控制台时，偶尔弹一次『配置已从文件重新导入』，而且提示之前几秒按键失效」。
一眼定位的办法：看 `logs/main.log` 里重载记录的时间间隔 —— **全是 4 秒的整数倍**
就说明是那个 4 秒轮询在误报，不是真有外部改动。

**-4. 版面放不下的那次重构（"UI 没法用"的真正原因）**
窗口默认 900×620，而 `.grid`(6×108px+间距+内边距)=728px + `aside` 最小 260px +
`main` 内外边距 60px = **最小需要 1048px**。结果：横向滚动条出现 → 又吃掉高度 →
第三行格子被裁、属性面板被挤成约 70px 的一条缝、输入框全被切掉。
**这不是审美问题，是算术问题。** 现在窗口默认 1160×800 / 最小 1000×660，
格子改用 `repeat(6, minmax(0,1fr))` + `aspect-ratio` 自适应，
并加了回归测试断言「任何尺寸下都无横向/纵向溢出、18 个格子全部可见」。
（排查手段：`npm run shot` 把界面截成 PNG 亲眼看 —— 这也是第一次真正"看见"这个 UI。）

**-3. `detached: true` 会让子进程弹出一个控制台窗口**
Node 官方文档原话：Windows 上 detached 的子进程 "**will have its own console
window**"。而 `windowsHide: true` **压不住它** —— 实测（`npm run probe:windows`）：

| 配置 | 结果 |
|---|---|
| `shell:true + detached:true + windowsHide:true` | ✗ 弹出控制台窗口 |
| `shell:true + windowsHide:true`（**去掉 detached**） | ✓ 完全静默，命令照常执行 |
| `cmd.exe /d /s /c "<line>"` | ✓ 静默但**命令根本没执行**（引号被 Node 重新转义） |

这台机器把默认终端设成了 **Windows Terminal**，所以窗口是以 WT 的样子弹出来的，
标题就是那行命令（用户看到的是「findstr /i akp153」）。
一个 `unref()` 就够了，**永远不要加 `detached`**。

**-2. 单实例应用：按了没反应，其实程序早就在跑**
`QOwnNotes`、微信开发者工具、VS Code 这类应用**只允许跑一个实例**。第二个进程启动后会
把参数交接给已有实例然后自己退出——**`shell.openPath()` 返回成功，`spawn()` 也不报错，
但屏幕上什么都不会发生**。

这是"按了没反应"最常见的假象，而且**旧代码的 `spawn` 也一样会中招**
（实测：`spawn(QOwnNotes.exe)` 在已运行时同样不产生新进程）。

所以现在 `.exe` / `.lnk` 按下时**先查进程**：
1. 已在运行 → 用 `WScript.Shell.AppActivate(pid)` 把主窗口唤到前台（不再重复启动）
2. 没在运行 → 正常 `openPath` 启动

`logs/main.log` 里能看出走的是哪条：`result: ok (focused)` = 唤起了已有窗口，
`result: ok (launched)` = 新启动。想验证直接跑 `npm run test:launch`。

**-1. `.lnk` 和部分 exe 用 spawn 起不来**
`child_process.spawn` 走的是 CreateProcess，**不能执行 `.lnk`**（快捷方式不是可执行文件），
报错是 `spawn EFTYPE`。部分安装器也一样。
除非需要传参数，否则一律改用 `shell.openPath()`（走 ShellExecute）——它能处理
exe / lnk / 文件夹 / 文档，还会自动解析快捷方式。需要参数时才用 spawn。

**0. 拖拽拿不到真实路径**
**Electron 32 删掉了 `File.path`**，在 Electron 38 上 `dataTransfer.files[0].path` 是 `undefined`。
回退到 `file.name` 就只剩一个文件名，再被 `path.resolve` 一拼，目标全变成了**应用自己的目录**
（症状：每个格子的目标是 `...\akp153-dock\你拖的文件名`，按下去报"Windows 找不到文件"）。
必须在 **preload** 里用 `webUtils.getPathForFile(file)` 取：
```js
// preload.js
const { contextBridge, webUtils } = require('electron');
contextBridge.exposeInMainWorld('api', { pathForFile: (f) => webUtils.getPathForFile(f) });
```
另外拖入前会先校验路径是否存在，不存在直接拒绝保存，不会再存进一堆坏路径。

**1. 命令里的引号和重定向会失效**
不要用 `spawn('cmd.exe', ['/c', line])`——Node 会为 CreateProcess 重新加引号，
cmd.exe 拿到的是一行被搞乱的字符串，`>` 重定向、管道、带引号的路径全部静默失效。
正确做法是 `spawn(line, { shell: true })`，等价于 `cmd.exe /d /s /c "<line>"`。
`tools/test-runner.js` 专门有一条「带空格 + 引号」的用例守着这个回归。

**2. 休眠状态下不要推图**
往已经休眠的面板推图片数据会让背光**部分回亮**，看起来就像"休眠只把亮度降到 1 而不是熄灭"。
驱动里 `draw()` 在 `asleep` 时直接返回，主进程的 30 秒时钟刷新也会跳过。

## 最新核心功能与进阶生态（已全部完成）

- **多页面与文件夹层级（Pages）**：无限层级树状页面管理，进入子页后右下角自动呈现物理返回键 `←`，支持整页快照存库与即时切页。
- **6 列大画布全景无缝渐变**：左侧 15 键 + 右侧 3 块副屏贯通连续渐变，文字自动计算对比度反色，副屏保留独立底色开关。
- **右侧副屏系统态势监控**：支持 `clock`（时钟）、`cpu`（CPU 占用率实时仪表）、`mem`（内存使用率实时仪表）、`sys`（综合态势）及自定义多行文字，极低开销静默采样。
- **原生虚拟快捷键 / 组合键宏 (`hotkey`)**：原生极速触发 `Win+D`（显示桌面）、`Alt+F4`（关闭窗口）、`Ctrl+Shift+Esc`（任务管理器）、`Win+E`、`Win+L`、`Ctrl+Alt+A` 及任意自定义组合键，无控制台黑框。
- **超长文本智能折行与字号自适应**：中英文/标点智能折行，超宽自动平滑微调字号兜底，消除物理亚克力键帽边缘遮挡。
- **本地图片 1:1 可视裁剪压缩器 (Image Cropper)**：拖入或选择本地图片时提供正方形裁剪视口，支持鼠标平移、滚轮/滑块缩放，重采样输出 192×192 极速高清图并压缩至 10KB 左右，保证硬件锐利且配置文件轻盈。
- **快捷方式与自定义文件夹图标穿透**：自动穿透 `.lnk` 解析至真实可执行文件与启动参数；自适应解码 UTF-16LE / ANSI `desktop.ini` 并调用 Windows API 提取 DLL/EXE 索引图标。
- **图标生态与用户自定义图标库**：内置 120+ 矢量 SVG 图标库；支持一键将当前按键调整好的图标（含角标徽章）存入「我的收藏」库随时复用。
- **右键上下文菜单与键盘快捷键**：网格支持右键复制/剪切/粘贴/存库/清空，支持键盘方向键移动选择、`Ctrl+C`、`Ctrl+V`、`Del` 清空。
